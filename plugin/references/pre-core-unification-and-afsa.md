# PRE Core Unification and A.S.F.R.E.E Host Adapter

## Canonical identity

The canonical roadmap competency is **Progressive Roadmap Evaluator (PRE Core)**. The legacy name **RPEDS** remains the A.S.F.R.E.E host compatibility adapter and historical vocabulary. Both names resolve to one logical roadmap lifecycle, one core release lineage and one set of canonical R0–R9 semantics.

The merger is functional, not a blind copy of every host instruction. PRE Core owns the roadmap lifecycle. A.S.F.R.E.E M00 owns case-level orchestration and final arbitration. Existing RPEDS references, schemas and four modules remain compatible entry points while their behavior maps to canonical PRE subskills. No parallel RPEDS roadmap database or duplicate milestone owner is permitted.

## Adaptive Functional Situational Adapter (AFSA)

AFSA is mandatory before host-integrated PRE behavior is applied. It resolves the exact host profile, PRE release/digest/contract, applicable SOP/policy version, decision rights, data class, permissions, tools, audit sink and rollback path.

Precedence: law/platform constraints → A.S.F.R.E.E approved SOP/security/privacy → M00 decision rights and delegated authority → PRE Core capability contract → convenience. A lower layer cannot weaken a higher one.

Disposition is one of:

- `DIRECT_COMPATIBLE` — use the shared behavior unchanged.
- `ADAPTED_COMPATIBLE` — use a documented deterministic adapter approved by the correct host authority.
- `HELD_FOR_AUTHORITY` — require policy interpretation or approval.
- `QUARANTINED_OR_REJECTED` — do not adopt unsafe, unauthorized, unlicensed, contradictory or incompatible material.

## Release synchronization

The A.S.F.R.E.E adapter subscribes to the canonical PRE release identity and returns a per-release adoption receipt. Automatic application is permitted only for verified additive/non-breaking capabilities that pass AFSA, contract checks and host regression tests under an already approved mapping. Changes to security, privacy, authority, permissions, license, data flow, required schemas or SOP require a gated PR/approval. Preserve the previous known-good version and rollback reference.

A webhook acknowledgement is not adoption. Verify target manifest, expected skills/schema inventory, exact version/digest, CI result and read-back before marking a host as updated. This source contract is an implementation candidate; live event credentials, persistent registry and deployed worker must be evidenced separately.

## Authority boundaries

- M00: only case-level coordinator and final arbitration.
- O11: authorization, security, privacy and access governance.
- O12: independent evaluation criteria, measurement validity and judgment.
- O10: test execution, independent verification and acceptance evidence.
- O09: supported runtime/API/MCP/integration execution.
- O07/O08: accepted remediation/reconstruction design and transformation.
- PRE Core/RPEDS: roadmap design, iterative progress, roadmap evaluation coordination, adaptive replan proposal and process traceability.

PRE never self-approves, self-verifies, grants access or declares a host deployment complete without read-back evidence.
