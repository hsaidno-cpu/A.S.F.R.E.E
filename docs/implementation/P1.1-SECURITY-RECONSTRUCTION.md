# A.S.F.R.E.E P1.1 Security Reconstruction — Evidence and Status

**Purpose:** record the P1.1 target architecture, acceptance contract and known verification boundary.

## Baseline facts

The current canonical repository baseline is plugin package v0.3.2 and a local P1 reference runtime v0.2.0. P1.0 contains OIDC validation logic, default-deny policy facades, tenant-derived local partitions, blob envelope-encryption contracts, and a fail-closed OCI command/preflight adapter. Its existing runtime tests include mocked provider/execution paths. Those facts do not prove a production IdP, MFA policy, KMS/HSM, encrypted live metadata/WAL/logs/backups, external WORM anchoring, independent cloud tenant boundaries, or real hostile-workload containment.

## Four P1.1 workstreams

1. **Identity & SCIVE:** verified IdP assurance mapping, fresh step-up authentication, asymmetric cross-process delegation, replay/revocation protection, tenant/action/resource binding, and a policy facade on every SCIVE transition.
2. **Encryption:** managed key custody; envelope encryption; encrypted metadata DB, WAL/SHM, temporary files, audit, logs, exports and backups; rotation and restore evidence.
3. **Execution:** provisioned rootless OCI plus gVisor/Kata or reviewed equivalent; host-level cgroup/IO/time/output quotas; streaming log limits; malicious-workload and cross-tenant isolation testing.
4. **Trust infrastructure:** external signed WORM audit anchors with read-back, infrastructure-enforced tenant isolation, concurrency/resilience tests, and independent signed human review.

Normative requirements and release decision gates are in the plugin reference [P1.1 Security-to-Production Readiness Contract](../../plugin/references/p1.1-security-production-readiness.md).

## Implementation status for this repository change

This branch updates the portable plugin's normative instructions, governance and acceptance specifications. The extended local runtime prototype and its 141-test local run are not yet part of this repository branch's tracked implementation bundle. They must not be represented as committed code or as this branch's CI evidence.

The P1.1 acceptance fixtures are specifications until the corresponding tests are integrated and executed. Any runtime implementation added later must be stored as a checksum-pinned source overlay and reconstructed by CI, with exact artifact provenance.

## Observed environment blocker

The available local execution environment exposed cgroup v2 controller files but did not have Docker/rootless Docker, runsc/gVisor, or a signed host quota agent available; execution under the available runner identity was root rather than a provisioned rootless worker. Therefore real isolated execution and hostile-workload containment were not run. Production execution readiness remains BLOCKED.

## Release disposition

Current P1.1 status is **ARCHITECTURE_AND_ACCEPTANCE_CANDIDATE**. Production is **NOT_READY** pending provider and host provisioning; integration against the selected IdP, KMS/HSM, database encryption engine, WORM store and OCI backend; hostile-workload, cross-tenant, concurrency, key-rotation and restore testing; independent human security review; and successful staging and production read-back under explicit approval.
