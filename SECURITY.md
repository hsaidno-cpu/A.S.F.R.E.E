# Security Policy

## Scope

Report vulnerabilities in the A.S.F.R.E.E source, plugin instructions, schemas, integrations or project infrastructure. Do not include secrets, customer data or exploit payloads in public issues.

## Reporting

Until a private security contact is published, do not open a public issue containing exploitable details. Use the repository owner's verified private contact/channel. If no secure channel is available, report only a high-level placeholder in public and withhold sensitive details until a secure route is established.

## Testing rules

Only test systems you own or are explicitly authorized to assess. No credential theft, authentication bypass, privilege escalation, destructive testing or unauthorized probing is permitted under this project.

## Handling

Maintainers should acknowledge receipt, reproduce only in an authorized isolated environment, assess impact, minimize disclosure and publish a fix/advisory when safe. Timelines and a formal disclosure SLA are not yet defined.
